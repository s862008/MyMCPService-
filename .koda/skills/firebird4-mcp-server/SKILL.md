# Работа с Firebird MCP Server (Firebird 4.0)

MCP-сервер `firebird` предоставляет инструменты для Firebird 4.0.
Все вызовы идут через протокол MCP (tools/call).

## Особенности Firebird 4.0

### Аутентификация (частая проблема подключения)
- FB4 по умолчанию использует **Srp256**. Учётные записи, созданные на FB3
  (Srp), работают, но пароли, сохранённые через Legacy (Social), — нет.
- Если ошибка подключения вида "plugin not supported / password incorrect":
  в `firebird.conf` сервера требуется
  `AuthServer = Srp, Legacy_Auth` и `WireCrypt = Enabled` (или Disabled для отладки),
  либо пересоздать пользователя: `CREATE USER ... PLUGIN Srp`.
- На стороне MCP-сервера менять ничего не нужно — Jaybird 5.x поддерживает
  Srp, Srp256 и Legacy_Auth автоматически.

### Диалекты
- Диалект 1 **deprecated**: работает, но FB4 пишет предупреждения в лог сервера.
- Для новых объектов используйте `dialect = 3` (параметр `mcp-config.ini`).
- Если база старая и на диалекте 1 — не меняйте её диалект через конфиг:
  диалект создания БД фиксирован, параметр dialect в URL лишь задаёт режим
  разбора запросов.

### SQL-улучшения FB4 (доступны агенту)
- **PSQL-модули и Package'и**: `CREATE PACKAGE` / `CREATE PACKAGE BODY` —
  группируют процедуры/функции. Для создания используйте `sql_execute`
  (обёртка `sql_create_procedure` генерирует только обычные процедуры).
- **Улучшенный PSQL**: `FOR SELECT ... DO` без курсора, оператор `RETURN`
  в блоках, `EXECUTE BLOCK` с RETURNS работает привычно.
- **Оконные функции** (если диалект 3): `SUM(x) OVER (PARTITION BY ...)`.
- **REGEXP()/SIMILAR TO** в WHERE доступны стабильно.
- **DEFAULT для GENERATED-колонки**: `GENERATED BY DEFAULT AS IDENTITY` —
  альтернатива генератору+триггеру:
  ```
  CREATE TABLE T (ID INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY)
  ```
  В FB4 это предпочтительнее связки GEN_ID+триггер для новых таблиц.

### Мониторинг
- MON$ расширен: `MON$STATEMENTS.MON$CALL_STACK`, `MON$IO_STATS` и др.
- `sql_explain` на FB4 получает план надёжнее (через статистику Jaybird).
- Для анализа нагрузки агент может читать MON$ напрямую через `sql_query`
  (требуются права, обычно SYSDBA):
  `SELECT MON$SQL_TEXT, MON$STAT_ID FROM MON$STATEMENTS WHERE MON$STATE = 1`

## Рабочий порядок (обязательно соблюдать)

1. **Разведка схемы**: `sql_list_tables` → `sql_describe_table` {table}.
2. **Валидация** сложного запроса: `sql_explain` {query}.
3. **Выполнение**: `sql_query` (SELECT) / `sql_execute` (DML/DDL).

## Инструменты

- `sql_query` {query} — только SELECT.
- `sql_list_tables` {}, `sql_list_procedures` {} — список объектов.
- `sql_describe_table` {table}, `sql_describe_procedure` {procedure} — схема.
- `sql_explain` {query} — валидация SELECT + план.
- `sql_execute` {query} — INSERT/UPDATE/DELETE/CREATE/ALTER/DROP/EXECUTE,
  а также CREATE PACKAGE / CREATE FUNCTION / CREATE SEQUENCE.
- `sql_create_procedure` {name, parameters?, returns?, body} — процедура.
- `sql_execute_procedure` {procedure, parameters:[]} — вызов процедуры.
- `sql_create_view` {name, query}, `sql_create_trigger` {name, table,
  timing, event, body} — обёртки DDL.

## Типичные задачи (FB4-стиль)

### Пример: таблица с IDENTITY вместо генератора (FB4+)
```
sql_execute:
CREATE TABLE ORDERS (
  ID INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  CLIENT_ID INTEGER NOT NULL,
  TOTAL DECIMAL(12,2) DEFAULT 0,
  CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP
)
```
Триггер и генератор НЕ нужны — IDENTITY сама выдаёт значения.

### Пример: пакет PSQL (FB4)
```
sql_execute:
CREATE PACKAGE PKG_ORDERS AS
BEGIN
  PROCEDURE ADD_ORDER (CLIENT_ID INTEGER, TOTAL DECIMAL(12,2)) RETURNS (NEW_ID INTEGER);
END

sql_execute:
CREATE PACKAGE BODY PKG_ORDERS AS
BEGIN
  PROCEDURE ADD_ORDER (CLIENT_ID INTEGER, TOTAL DECIMAL(12,2)) RETURNS (NEW_ID INTEGER)
  AS BEGIN
    INSERT INTO ORDERS (CLIENT_ID, TOTAL) VALUES (:CLIENT_ID, :TOTAL) RETURNING ID INTO :NEW_ID;
  END
END
```

### Пример: вызов процедуры с RETURNING
```
sql_execute: EXECUTE PROCEDURE ADD_ORDER(5, 150.00)
-- вернёт строку NEW_ID
```

## Безопасность

- В `sql_query` проходит только SELECT (сервер отклонит остальное).
- DDL необратим — перед DROP/ALTER подтвердите у пользователя.
- Результаты SELECT ограничены 10000 строк.

## Ошибки

Ответ с `isError: true` содержит полный текст ошибки Firebird
(SQLCODE, GDSC, вложенные причины) — исправляйте SQL по тексту.
Для ошибок вида "no permission for MON$..." — не читайте MON$ без нужды.
