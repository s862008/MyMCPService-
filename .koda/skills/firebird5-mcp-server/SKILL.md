# Работа с Firebird MCP Server (Firebird 5.0)

MCP-сервер `firebird` предоставляет инструменты для Firebird 5.0.
Все вызовы идут через протокол MCP (tools/call).

## Особенности Firebird 5.0

### Аутентификация и безопасность (FB4 → FB5 эволюция)
- **WireCrypt по умолчанию включён** (AES) — старые клиенты без шифрования
  не подключатся. Jaybird 5.x шифрование поддерживает, на стороне MCP-сервера
  ничего менять не нужно.
- Конфигурация пользователей вынесена в **security2.fdb**:
  `gsec` устарел, управление через `isql`: `CREATE/ALTER/DROP USER`.
- **Табличные права**: `GRANT ... ON TABLE TO ROLE` работают как в FB4.
- Ошибки подключения ("Handshake error", "Incompatible wire encryption") —
  проблема конфига сервера FB (firebird.conf), а не MCP-сервера.

### Что изменилось относительно FB4 (важно для SQL)
- **Производительность метаданных**: частые запросы к RDB$-таблицам
  (наши `sql_list_tables`/`sql_describe_table`) работают заметно быстрее.
- **Расширенный MON$**: новые колонки `MON$STATEMENTS.MON$SQL_TEXT` (полный
  текст), `MON$CALL_STACK_DEPTH`, `MON$PARENT_STATEMENT_ID` — удобнее трассировка.
- **JSON-функции** (экспериментально): `JSON_VALUE`, `JSON_EXISTS` — можно
  работать с JSON в VARCHAR без внешних UDF.
- **Удалено легаси**: старые API `isc_*` и часть устаревших op-code'ов —
  на JDBC/Jaybird это НЕ влияет.
- **Диалект 1**: по-прежнему работает, но официально deprecated —
  новые базы создавайте сразу с `dialect = 3`.

### Рекомендации агенту
- Пишите SQL в **диалекте 3** (TRUE/FALSE, TIMESTAMP, IDENTITY) —
  см. skill `firebird-dialect3-mcp-server`.
- Для новых таблиц используйте `GENERATED BY DEFAULT AS IDENTITY`
  вместо генератор+триггер.
- Для анализа запросов: `sql_explain` + чтение MON$ через `sql_query`.

## Рабочий порядок (обязательно соблюдать)

1. **Разведка схемы**: `sql_list_tables` → `sql_describe_table` {table}.
2. **Валидация** сложного запроса: `sql_explain` {query}.
3. **Выполнение**: `sql_query` (SELECT) / `sql_execute` (DML/DDL).

## Инструменты

- `sql_query` {query} — только SELECT.
- `sql_list_tables` {}, `sql_list_procedures` {} — список объектов.
- `sql_describe_table` {table}, `sql_describe_procedure` {procedure} — схема.
- `sql_explain` {query} — валидация SELECT + план.
- `sql_execute` {query} — INSERT/UPDATE/DELETE/CREATE/ALTER/DROP/EXECUTE,
  CREATE PACKAGE, CREATE FUNCTION, GRANT.
- `sql_create_procedure` {name, parameters?, returns?, body} — процедура.
- `sql_execute_procedure` {procedure, parameters:[]} — вызов процедуры.
- `sql_create_view` {name, query}, `sql_create_trigger` {name, table,
  timing, event, body} — обёртки DDL.

## Типичные задачи (FB5-стиль)

### Пример: таблица с IDENTITY и JSON-колонкой
```
sql_execute:
CREATE TABLE EVENTS (
  ID BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  EVENT_TYPE VARCHAR(30) NOT NULL,
  PAYLOAD VARCHAR(4000),
  CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP
)
```

### Пример: запрос с JSON_VALUE (FB5)
```
sql_query:
SELECT ID, EVENT_TYPE,
       JSON_VALUE(PAYLOAD, '$.user.name') AS USER_NAME
FROM EVENTS
WHERE JSON_EXISTS(PAYLOAD, '$.user.id')
```

### Пример: трассировка активных запросов (нужны права)
```
sql_query:
SELECT s.MON$STATEMENT_ID, s.MON$SQL_TEXT, a.MON$USER, a.MON$REMOTE_ADDRESS
FROM MON$STATEMENTS s
JOIN MON$ATTACHMENTS a ON a.MON$ATTACHMENT_ID = s.MON$ATTACHMENT_ID
WHERE s.MON$STATE = 1 AND s.MON$SQL_TEXT NOT CONTAINING 'MON$'
```

## Безопасность

- В `sql_query` проходит только SELECT (сервер отклонит остальное).
- DDL необратим — перед DROP/ALTER подтвердите у пользователя.
- Результаты SELECT ограничены 10000 строк.
- Мониторинг MON$ раскрывает запросы и пользователей — читайте только по задаче.

## Ошибки

Ответ с `isError: true` содержит полный текст ошибки Firebird
(SQLCODE, GDSC, вложенные причины) — исправляйте SQL по тексту.
Ошибки аутентификации/шифрования — правьте firebird.conf/security2 на сервере FB.
